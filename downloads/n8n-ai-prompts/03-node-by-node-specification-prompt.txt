قالب 3 — تجهيز مواصفات العُقد على مراحل

المعمارية السابقة معتمدة. لا أريد منك إنشاء ملف Workflow كامل مرة واحدة.

سنقسم البناء إلى مراحل صغيرة، وفي كل مرحلة سنراجع من 4 إلى 6 Nodes فقط.

ابدأ بالمرحلة الأولى من المعمارية المعتمدة.

لكل Node اكتب بالترتيب:
1. الاسم النهائي للـNode.
2. النوع الرسمي الكامل في n8n.
3. وضع التشغيل إن كان له أكثر من وضع، مثل Run Once for All Items أو Run Once for Each Item.
4. Resource / Operation إن كان ذلك ينطبق على الـNode.
5. أهم Parameters المطلوبة.
6. البيانات الداخلة المتوقعة.
7. البيانات الخارجة المتوقعة.
8. جميع Expressions المطلوبة.
9. إعداد On Error المناسب وسبب اختياره.
10. نوع Credential المطلوب فقط، دون أي بيانات اعتماد فعلية.
11. كيفية الحفاظ على Item Linking أو pairedItem إذا كانت Code Node تغيّر عدد العناصر أو تعيد بناءها.
12. أسماء الـNodes السابقة واللاحقة التي تتصل بها.
13. إذا كانت Code Node، اكتب الكود كاملًا وقابلًا للنسخ دون اختصار.

قواعد مهمة:
- لا تغيّر المعمارية المعتمدة دون أن تخبرني وتوضح السبب.
- لا تستخدم Merge لدمج فروع متنافية إذا كان ذلك قد يجعل التنفيذ ينتظر فرعًا لن يصل.
- لا تفترض أن ناتج خدمة خارجية له شكل ثابت عند الخطأ؛ صمّم فحصًا واضحًا لحالة النجاح والفشل.
- لا ترسل تنبيه نجاح قبل التأكد من نجاح العملية الأساسية التي يصفها التنبيه.
- حافظ على Item واحد واضح يعود إلى الحلقة الرئيسية لكل عنصر تتم معالجته.

بعد إنهاء هذه المرحلة توقّف وانتظر مراجعتي قبل الانتقال للمرحلة التالية.
